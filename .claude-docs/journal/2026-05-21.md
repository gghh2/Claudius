# Journal — 2026-05-21

## Contexte

Lancement de la feature « LLM local » (choix Cloud / Local pour le moteur d'IA).
Une longue discussion de conception, puis l'implémentation des fondations.

## Décisions de conception

Débat sur l'hébergement du LLM (échange en mode « Rodin ») :

- **Auto-hébergement AWS écarté** comme backend joueur. Le serveur disponible
  est un `t3.medium` (2 vCPU burstable, 4 Go, sans GPU) : inadapté à l'inférence
  soutenue. Et un jeu *distribué* qui taperait ce serveur = on paie l'inférence
  de tous les joueurs + single point of failure.
- **Ollama en dev**, **LLMUnity (modèle embarqué) comme défaut au build**,
  **OpenAI en option « bring your own key »**. La distribution prévue (zip puis
  Steam) rend le surpoids du modèle acceptable — Steam delta-patch un fichier
  qui ne change pas.
- Le LLM local devient le *défaut*, pas le repli : un jeu distribué ne peut pas
  exiger une clé OpenAI de chaque joueur.

## Fait — Phases 0 & 1

### Phase 0 — modèle porté par le provider
- `AIRequest.model` devient un override optionnel ; chaque provider connaît son
  modèle par défaut.
- Quick win : le modèle cloud passe de `gpt-3.5-turbo` à `gpt-4o-mini` (moins
  cher et meilleur). Le `"gpt-3.5-turbo"` en dur d'`AdventureJournalUI` retiré.

### Phase 1 — provider compatible OpenAI + Ollama
- `OpenAICompatibleProvider` : toute la logique HTTP, partagée. `OpenAIProvider`
  et `OllamaProvider` réduits à des préréglages (URL + modèle par défaut).
- `AIService` résout le provider depuis une préférence (`PlayerPrefs`).
- Menu éditeur `Tools > Claudius > IA` pour basculer Cloud / Ollama en dev.

### Validation
- Banc d'essai HTTP (Qwen2.5-3B sous Ollama) : GPU OK (modèle 100 % en VRAM sur
  la RTX 3090), latence à chaud ~2,7 s, à froid ~34 s (chargement VRAM), UTF-8 OK.
- En jeu : un PNJ piloté par le Qwen local tient un dialogue cohérent et produit
  un token `[QUEST:EXPLORE:ruins]` valide.

## Reste

- Phase 2 : repli propre quand le moteur local est injoignable.
- Phase 3 : sélecteur Cloud / Local dans le menu Options.
- Phase 4 : intégration LLMUnity (modèle réellement embarqué dans le build).
- Phase 5 : évaluation des modèles (taux de tokens valides) + tuning des
  prompts pour petit modèle ; cold-start à masquer par un préchauffage.
